## §0 — How to use this file

### 0.0 This is a prompt, not a report

Every section below is either a **ruling** (a decision already made), a **rule** (a constraint the work must satisfy), an **open question** (§0.6 — answer before building), or a **directive** (§11 — what the next workflow executes). Nothing here is narration. When a section contradicts the code, the code wins and the contradiction is a defect to file, not a spec to follow.

### 0.1 Epistemic rules — bind every agent that reads this file

- **R1 — The code is the only authority on what exists.** Never cite a file you have not opened with Read. `docs/`, comments, doc-comments, ADRs, README, commit messages, and *this file* are all non-authoritative about current behavior. A prior sweep in this session invented `docs/adr/0001-ui-adopts-margiela-design-system.md` and `docs/adr/0002-camera-chrome-stays-visible.md` and quoted them as pre-existing authority. `git log --all --diff-filter=A` shows **neither file was ever tracked**. `CONTEXT.md` never existed either. Do not repeat this error.
- **R2 — Every claim carries a citation**: `file:line` for code, URL for web, `spec-file:line` for this spec set.
- **R3 — Doc/code mismatch is itself a defect.** If a comment says one thing and the code does another, file the comment as wrong. Do not "reconcile" by trusting the comment.
- **R4 — Owner statements in conversation outrank every spec, including this one.** They are instructions, not documentation.
- **R5 — Never claim tests pass without running the test action and quoting its output.**
- **R6 — Everything is derived in the functional paradigm** (sinthink, §1). Pure functions, values over mutations, typed error channels, dependencies as explicit requirements.
- **R7 — Mark provenance.** A value is either `OBSERVED` (from code or a fetched source), `DERIVED` (computed from observed values, e.g. contrast ratios), or `PROPOSAL` (authored, owner-approved direction, implementer-pinned). Never present a PROPOSAL as OBSERVED.

### 0.4 ⚠ THE TWO POLES — read before anything else

The five specs are internally detailed and externally **contested**. A house-literate critic read all five and returned a verdict that cannot be ignored, because it attacks the premise rather than the details:

> *"Zero radius + hairline + uppercase mono + black/white inversion is COS / Jil Sander / Apple-light-mode / every brutalist camera clone. Nothing here requires Margiela to explain it. You could swap the word 'Margiela' for 'teenage grayscale Figma kit' and change zero tokens."*

It is correct, and the reason is structural: the specs kept the **typewriter** (the part any iOS app can have for free) and dropped everything that makes the house the house — the crooked hand-sewn tack, white-on-white, the basting stitch deliberately left in, the refusal to explain. The full objection is §9; it is part of this prompt, not an appendix to it.

So the design must be chosen between two poles, and **the owner must choose** (§0.6 Q1):

**Pole A — BASELINE.** The five specs as written. Quiet monochrome minimalism. Radius 0, hairlines, uppercase Courier New, black/white inversion, a detailed state matrix, a full accessibility layer, a metadata sheet, honest-bypass copy. Shippable now, testable, defensible. And, per the critic, **generically so** — it would survive having the word "Margiela" deleted from it.

**Pole B — ANONYMITY.** The critic's direction. Sewn tack-stitches instead of underlines; tags that are genuinely blank; no manifesto copy; no EXIF/provenance sheet; no dates, counts, or ordering-as-identity; the house "faxes, it does not onboard." Far closer to the actual house. It gives up, in the critic's own words, *"almost everything these specs are proudest of."*

**Recommended: a HYBRID, and it is asymmetric.** Politeness to the argument requires taking Pole B's *cheap, high-signal* moves and Pole A's *expensive, invisible* work:

| Take from Pole B (cheap, decisive) | Keep from Pole A (expensive, invisible) |
|---|---|
| **Sew the selection.** Four loose tack-stitches replace the underline — §9.5 | The token layer (`Room`/`Ink`/`Type`/`Rule`/`Space`) |
| **Blank the tag.** No wordmark on the mark component | The 37-state matrix (§5) |
| **Delete the Tabi split** on the thumbnail — merch-table graphics | The accessibility layer (§6) |
| **Delete numbered modes** (`0` capture / `1` gallery / `22` export) — retailer lore, and the spec admits it | The identifier contract, updated in the same change |
| **Delete the manifesto strip.** One `DNG` mark, no `ZERO PROCESSING AT CAPTURE — NO ENHANCEMENTS ADDED` | The lint (§8) |
| **Strip the DATA sheet** to the DNG tags *raw*, no `BYTES`/`SENSOR`/`EXPOSURE`/recipe list | The white room, the grid, the viewer geometry |
| **Drop "Margiela" from every symbol name.** `enum Room` not `MargielaTheme` — §9.4 | The contrast math, scrim system, Dynamic Type mapping |

The last row is free and the critic's sharpest point: *"the house refuses the author's name; you ship it as a type name in every view file."* Naming an `EnvironmentKey` after the house is the opposite of anonymity. There is no cost to not doing it.

**Pole B's one hard collision with the product.** The critic wants the honest-bypass surface deleted as "Protestant, didactic, self-congratulatory." But ruling #1 says the bypass *is the feature*. A camera that bypasses post-filtering and refuses to say so is indistinguishable, to the user, from a camera that does nothing. **Resolution ruling:** the bypass is expressed by **absence**, not by manifesto. The `DNG` mark is the only claim. No enhancement words appear anywhere. What the app does not do, it does not mention — which is both the house position *and* the stronger claim, because it is the one a competitor cannot copy by writing copy. See §0.5 #12.

## §1 — sinthink applied to design

The design is a program. It has a call graph, an error channel, and dependencies. Derive it the same way as any other program.

### §1.1 — Shapes: the nouns

**Records** — the values that flow through the design graph:

```
Ink, Type, Rule, Space   — the token values (see §2)
Room                     — the environment a surface renders in
Word                     — a string from the closed vocabulary (§7.1)
ControlState             — rest | pressed | selected | disabled
Phase                    — idle | countdown | capturing | savingDNG  (CameraViewModel.swift:20-29)
```

**IDs** — identity. Per sinthink, *"branded, constrained, never a bare string."* The accessibility identifiers are simultaneously (a) the design's identity, (b) the UI-test contract, and (c) what VoiceOver reads. They are the single most load-bearing type in this design:

```swift
struct ControlID: RawRepresentable, Hashable {
  let rawValue: String            // "camera-shutter", "room-delete", …
}
enum ControlIDRegistry { static let all: [ControlID] }   // the lint iterates this (§8)
```

A bare `"camera-shutter"` string literal anywhere in a view is a lint failure — it must come from the registry, so that renaming is a one-line change and the test contract cannot drift from the design.

**Variants**:

```swift
enum Room       { case black, white }
enum RuleTone   { case primary, soft }
enum ControlState { case rest, pressed, selected, disabled }
```

**Errors** — the design's E channel. See §1.4.

### §1.2 — A first: the design's happy path

Draw the call graph before styling anything:

```
Screen ──> Room ──> Tokens ──> WordControl* ──> Word
  │         │          │            │            │
  │         │          │            │            └─ a string from the closed vocabulary
  │         │          │            └─ Button + MargielaType(.label) + 44pt target + tack(selected)
  │         │          └─ Ink/Type/Rule/Space resolved against Room
  │         └─ .black | .white  (Environment)
  └─ Camera | Gallery | Viewer | Permissions
```

The happy path is: a screen declares its room, resolves tokens, renders words, a tap changes state, the new state re-renders. **That is the whole program.** No view computes a color; no view knows a hex; no view decides a size. If a `body` contains `.foregroundStyle(.yellow)`, the call graph above has been bypassed — that is exactly the failure §1.10 names.

### §1.3 — Cardinality: one-shot or stream?

Mark each node, because the code has to match:

| Node | Cardinality | Why |
|---|---|---|
| `WordControl` tap | **Effect** (one value) | a press produces one action |
| `Phase` machine | **Effect** | one current phase; transitions are single values |
| Live preview | **Stream** | frames arrive continuously |
| Countdown | **Stream** | one tick per second, bounded by the timer |
| Gallery `captures` | **Stream** | the library mutates under `watchInvalidation` |
| `thumbnails` per cell | **Stream** (cached) | time-bounded; dedupe concurrent loads |

The design consequence: **anything drawn over the live preview must tolerate being redrawn at frame rate.** That is why the chrome is a static scrim + static words (§2.2), not an animating overlay. Anything whose cardinality is Stream must not own layout that reflows on each frame.

### §1.4 — E second: where the design breaks

Two error channels, and they must not be confused:

**Channel 1 — `DesignViolation` (compile/CI time).** A tagged enum, not a string. This is the design's E, and the lint (§8) is the pipe that enumerates it:

```swift
enum DesignViolation: Error {
  case rawRoundedType(File: String, Line: Int)          // .font(.system(design: .rounded))
  case capsuleOrCircleShape(File: String, Line: Int)    // Capsule()/Circle() outside the allowlist
  case iconInChrome(symbol: String)                     // Image(systemName:) in chrome
  case forbiddenColor(String)                           // .yellow, .red outside fail, literal .white/.black
  case dividerInsteadOfRule
  case fixedTypeWithoutRelativeTo(String)               // two-arg Font.custom
  case missingIdentifier(File: String, Line: Int)       // a control with no ControlID
  case contrastBelowAA(fg: String, bg: String, ratio: Double, required: Double)
  case tapTargetBelow44(pt: CGFloat)
  case bareWordsOverPreview(File: String, Line: Int)    // no scrim / no backing
}
```

Handling strategy, per sinthink §4:

- **Retry** — contrast below AA: adjust the token and re-render. Transient, mechanically fixable.
- **Escape hatch** — a token missing for a room: fall back to `ink` and *report*, never crash.
- **Die** — `rawRoundedType`, `capsuleOrCircleShape`, `iconInChrome`, `dividerInsteadOfRule`. These are programmer defects, not domain errors. In CI they **die**: the build fails. Do not "handle" them.

**Channel 2 — the runtime state matrix (§5).** 37 states, S01–S37. This is the *user-visible* E: what the screen says when the camera is denied, when storage is full, when a call interrupts a capture. Every one of these is a design obligation, and the completeness critic found that **11 classes of them have no visual treatment at all** (§10). A state with a proposed word but no type, colour, rule, or hit area is not designed — it is named.

### §1.5 — R third: what a view needs to exist

The design layer's `R` is deliberately tiny, because a small `R` is what makes the design *provable*:

```
R_design = Room            +  displayScale  +  colorScheme
         + DynamicTypeSize +  IncreaseContrast  +  ReduceTransparency  +  ReduceMotion
```

Per sinthink §5, `R` is compile-time proof that dependencies are satisfied. Here it is *environment*-time, which is the SwiftUI equivalent, **and the lint makes it checkable**: a view that forgot `.environment(\.room, …)` renders in the default room and the lint's room-coverage assertion (§8.3) fails. A view that hard-codes a colour has satisfied `R` by cheating, which is `DesignViolation.forbiddenColor`.

`R` shrinks to `never` when every screen is wrapped in exactly one `.environment(\.room, ...)` at its root: `CameraView` → `.black`, `GalleryView` → `.white`, `FullScreenViewer` → `.white`, `RootView` permission surfaces → `.black`.

### §1.6 — Trust at the boundary: the live preview

The viewfinder is the **untrusted input** of this design. Any content can appear behind the chrome — white sky, black night, a busy texture. Per sinthink §6, one Schema converts `unknown → trusted` at the edge, and there is exactly one here:

```swift
enum LegibilitySurface {                       // the Schema
  case scrim          // Black 45%→0%, 88pt, localized — default
  case opaqueBar      // Black 100%, 44pt strip — when Reduce Transparency is ON
}
func legibilitySurface(_ env: EnvironmentValues) -> LegibilitySurface
```

**Rule:** no word ever renders bare over the preview. Every over-preview word resolves through `legibilitySurface`. This is the single boundary parse in the design, and it is where contrast is guaranteed (4.5:1 normal / 3:1 large) rather than eyeballed. Trust nothing behind the words; trust everything inside the scrim.

### §1.7 — Pipe: behaviour that wraps without changing the graph

Per sinthink §7, cross-cutting design behaviour is composed orthogonally, so the happy path stays readable:

```swift
.margielaType(.label, selected:)   // font + tracking + case + ink, resolved from Room
.margielaRule(.primary)            // Rectangle().frame(height: 1/displayScale) in the room's rule ink
.tack(selected:)                   // four loose stitches (§9.5) — Pole B
```

A view that inlines `.font(...)` + `.foregroundStyle(...)` + `.textCase(...)` at a call site has put design behaviour *inside* the A path — the same defect as error handling inside an `Effect.gen` body. The lint forbids it.

### §1.8 — Scope: acquire/release tied to lifecycle

| Resource | Acquired | Released |
|---|---|---|
| `LegibilitySurface` scrim layer | when a word row enters the hierarchy | when it leaves |
| Tap-to-cancel subject | `Phase == .countdown` | phase leaves `.countdown` |
| `DevelopService` | viewer presentation | viewer dismissal — **currently leaks**; see §10 #7 |
| Torch | `flashOn` | capture end — **currently can stick on**; see §10 #6 |

Scope is a type guarantee, so cleanup is structural, not a TODO. Today two of these four are not: the torch can remain lit after a best-effort off (`code-digest.md:310`), and a zoom-restore error on the success path discards an already-captured DNG (`code-digest.md:311`). Both are filed in §10.

### §1.9 — Swap R to prove it

The view code does not change between production and test. Only `R` changes:

| Swap | Assertion |
|---|---|
| `Room.black` ⇄ `Room.white` | every screen renders correctly in both; no hard-coded colour survives |
| `IncreaseContrast` off ⇄ on | rules step to 2px, secondary → primary ink, still correct |
| `ReduceTransparency` off ⇄ on | scrim → opaque bar, still ≥4.5:1 |
| `ReduceMotion` off ⇄ on | all durations 0, still operable |
| `DynamicTypeSize .large` ⇄ `.accessibility5` | no clipping, no reflow break at 375pt and 440pt |

If a screen breaks under any swap, the design has a hidden dependency — it hard-coded something. **This is the payoff:** the design is proven by swapping the environment, not by mocking the world.

### §1.10 — `body` is A, modifiers are E

The separation maps directly onto SwiftUI:

- **The `View.body` is the happy path.** It reads as composition: a room, words, taps, state. It contains no colour literals, no font literals, no accessibility branches.
- **The modifiers are the E enumeration.** Every accessibility pressure the design must survive — contrast, transparency, motion, size — lives in `.margielaType` / `.margielaRule` / `.tack` / the scrim, not in the body.

The one legitimate exception (the sinthink "divergent strategy") is the **shutter**, which branches on `Phase` for its press/capturing behaviour. That branch is inline in `ShutterButton`, marked as the single permitted divergence, because the outer pipe cannot tell which phase produced it.

**A view with an inline `.yellow` has put design behaviour inside the A path. That is the whole test.**

## §7 — The delivery layer

One layer views opt into. Names carry **no house name** (§0.4, Pole B) — this is the critic's anonymity point honoured at zero cost.

```swift
enum Room { case black, white }
enum InkToken { case bg, ink, secondary, rule, ruleSoft, wash, scrim,
                      selectBg, selectInk, fail }
enum TypeToken { case display, title, body, label, caption, tick }
enum RuleTone { case primary, soft }

struct RoomKey: EnvironmentKey { static var defaultValue: Room = .black }
extension EnvironmentValues { var room: Room { get set } }

struct ChromeType: ViewModifier {
  let token: TypeToken
  var selected: Bool = false
  func body(content: Content) -> some View {
    content
      .font(ChromeFont.font(for: token, selected: selected))     // Font.custom(_, size:, relativeTo:)
      .tracking(ChromeFont.tracking(for: token))
      .textCase(ChromeFont.textCase(for: token))
      .foregroundStyle(ChromeInk.color(.ink, in: room))
  }
}

struct ChromeRule: View {
  let tone: RuleTone
  @Environment(\.displayScale) private var scale
  var body: some View {
    Rectangle().frame(height: 1 / scale)
      .foregroundStyle(ChromeInk.color(tone == .primary ? .rule : .ruleSoft, in: room))
  }
}

// The four loose tack-stitches of §9.5 — the selection signal, replacing .underline
struct Tack: View { let identity: Int; /* 4× 6×1.5pt rects, rotated ±4°, jittered by identity */ }

struct WordControl: View {
  let word: String
  let id: ControlID
  var selected: Bool = false
  var disabled: Bool = false
  let action: () -> Void
  var body: some View {
    Button(action: action) {
      Text(word)
        .modifier(ChromeType(token: .label, selected: selected))
        .overlay { if selected { Tack(identity: id.hashValue) } }   // sewn, not underlined
        .background(selected ? ChromeInk.color(.selectBg, in: room) : .clear)
        .padding(.horizontal, 12).padding(.vertical, 6)
        .frame(minWidth: 44, minHeight: 44)
    }
    .contentShape(Rectangle())
    .disabled(disabled)
    .accessibilityIdentifier(id.rawValue)
    .accessibilityLabel(word)
  }
}
```

**No symbol in this layer is named after the house.** `RoomKey`, `ChromeType`, `ChromeInk`, `ChromeRule`, `Tack`, `WordControl`. The design is anonymous; the code says so.

## §9 — The objection

This is the second critic's full verdict, retained **verbatim** because it is the strongest design input this project has received, and because §0.4 depends on it. It is not an appendix. Treat it as a direction layer the implementation must answer point by point.

> **1. This is generic quiet-minimal, not Margiela.**
>
> `spec-design-system-tokens.md:50` — *"PRIMARY AND ONLY CHROME FACE: Courier New."* That is not a house decision. That is stock iOS typewriter minimal. The specs themselves admit the real house face is `CourierNewRecast` with a 500-requested / 400-shipped gap, then spec the system fallback as the design. You kept the typewriter cliché and dropped the Recast cut, the bad ink, the misregistration — the only parts that made it Margiela.
>
> Zero radius + hairline + uppercase mono + black/white inversion is COS / Jil Sander / Apple-light-mode / every brutalist camera clone. Nothing here requires Margiela to explain it. You could swap the word "Margiela" for "teenage grayscale Figma kit" and change zero tokens.
>
> **2. What survives vs what is decoration.** Survives, barely: the blank tag without wordmark. `DEVELOPED COLLECTIVELY in type-caption, no names, no avatars, no bylines` — that is actually the house operating principle. Everything else is decoration. You turned the anti-logo into a logo component with exact pt, then lint-enforced it: *"Once you lint the anonymity, you killed it."* Numbers: house numbers 0–23 signify ateliers, not screen indices — *"numbering-as-wallpaper."* Trompe-l'oeil, exposed construction, replica/copy-as-original, anonymity-as-principle: **none survive.** Your "exposed seams" are dividers. The Tabi-split mark on a thumbnail is *"vulgar… merch-table graphics. Delete it."*
>
> **3. Specific misunderstandings.** (a) The house tacks are four WHITE stitches on white, barely visible, holding a BLANK label — you spec black ticks, 1pt border, exact positions: *"that is a bordered chip."* (b) Underline-as-selection comes from e-commerce link styling; *"the house does not underline the selected garment. Selection would be: inside-out, lining showing, tag exposed."* (c) *"Margiela never prints a manifesto on the garment explaining what was NOT done. The refusal to explain IS the position."* The honest-bypass copy is *"Protestant, didactic, self-congratulatory."* (d) Tracked-out uppercase words are not anonymity — *"it is a shouting foreman."*
>
> **4. The opposite of Margiela here.** The design SYSTEM itself — *"naming a SwiftUI EnvironmentKey `MargielaTheme` and lint-enforcing it is branding, gloss, self-congratulation. The house refuses the author's name; you ship it as a type name in every view file."* Second, the audit fetish: `FILE · BYTES · SENSOR · EXPOSURE` is *"provenance porn… Leica-style luxury auditing, not Parisian anonymity."* Third, white-room purity: *"the house white is dirty… plaster, atelier dust. Your white is `#FCFCFC` + verified `≥4.5:1`. That is not a white room. That is a cleanroom."* And the red inconsistency proves you don't believe your own monochrome: house truth on one screen, owner-rule violation on the next.
>
> **5. The one cheap SwiftUI move.** *"Stop underlining the selected word. Sew it."* Four loose tack-stitches: 6×1.5pt thread rects, rotated ±4°, positions jittered per view identity, drawn over the blank tag and the selected word, never pixel-snapped. *"It is the only house gesture that cannot be mistaken for minimalism — the hand, the basting stitch meant to be removed but left in."* Bonus: tacks differ per launch — *"anonymity means no two garments identical."*
>
> **6. What ANONYMITY would have to give up.** Almost everything these specs are proudest of: the DATA sheet, the date/identity headers, the didactic voice, `SHARE` on full-sensor originals with filenames attached.

### §9.5 — What the hybrid actually implements from this

**Ruling — the tack is the selection signal.** Replace `.underline(selected)` in `WordControl` with `Tack(identity:)`: four `6×1.5pt` rects, rotations drawn from a fixed per-identity table (not `Math.random()` — it must be deterministic for snapshot tests), jittered, never pixel-snapped, drawn **over** the word and over the blank tag. The base `identity` is the control's `hashValue`; a per-launch seed varies it within the table so no two launches are identical. Cost: one `Canvas` or four `Rectangle`s. This is the single highest-signal change in the whole document.

**Ruling — the tag is genuinely blank.** No wordmark, no line numbers, no tabi split.

**Ruling — no red in the white room** (§0.5 #6).

**Ruling — delete the manifesto** (§0.5 #12). The `DNG` mark is the claim.

**Ruling — drop the house name from every symbol** (§7).

**NOT taken from the critic:** deleting the token system, the state matrix, the a11y layer, or `DNG 03 / 11`. Those are the invisible, expensive work that the critic's own frame does not price. The house may be anonymous; the engineering is not free.
